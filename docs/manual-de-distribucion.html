RFlowP · Manual técnico

Cómo publicar la app y llevarla a cada aparato

RFlowP es una sola cosa —una aplicación web instalable— que se publica una vez y se instala distinto en cada sistema. Esta guía cubre dónde alojarla, cómo la instala cada alumno, y las dos vías nativas por si algún día hacen falta.

Ya está publicada

La app vive en https://rodolfoluna.github.io/rflowp/ y el código en github.com/rodolfoluna/rflowp. Cada cambio en main se publica solo, y no se publica si fallan las pruebas.

Dos reglas que mandan sobre todo lo demás

1 · Sin HTTPS la app no funciona. Nada de «casi»

El cifrado (crypto.subtle), el almacenamiento de archivos (OPFS) y el funcionamiento sin conexión exigen conexión segura. Servir la app desde http://192.168.1.50 en la red del laboratorio no sirve: la app carga a medias y falla al guardar. La única excepción es http://localhost en la propia máquina.

2 · La dirección es la identidad. Elígela antes de repartirla

Todo lo del alumno —su identidad, sus llaves, sus algoritmos guardados— vive atado a la dirección exacta desde la que abrió la app. Si mañana mueves la app de tec.github.io/rflowp/ a algoritmos.tec.mx, todos tus alumnos aparecen como nuevos y pierden el acceso a lo que guardaron. Tú podrás recuperar sus entregas con tu llave, pero es un trastorno para el grupo entero.

Decide el dominio definitivo antes del primer día de clase, aunque de momento apunte a algo provisional.

Dónde alojarla

Las cuatro opciones razonables, con lo que de verdad las diferencia:

Opción Costo Dominio propio Cuándo conviene
Cloudflare Pageso Netlify Gratis Sí La opción por omisión. HTTPS automático, se publica arrastrando la carpeta o conectando el repositorio, y admite dominio propio sin pagar.
GitHub Pages Gratis Sí Bien si el proyecto ya vive en GitHub. Ojo con la subcarpeta: hay que construir con RFLOWP_BASE (más abajo).
Servidor de la escuela Ya pagado Sí Si la institución exige que todo esté en su infraestructura. Necesitas que alguien de sistemas te dé HTTPS y una carpeta.
Red local sin internet Gratis No Solo si el laboratorio está aislado. Requiere montar HTTPS con certificado propio en cada equipo: es la opción más laboriosa con diferencia.

Construir la app

Con Node 20 o más reciente, dentro de la carpeta del proyecto:

npm ci
npm run build

Queda todo en la carpeta dist/. Eso es lo que se sube: son archivos estáticos, no necesitan servidor de aplicaciones ni base de datos.

Si la app va en una subcarpeta

Es el caso de GitHub Pages en un repositorio normal (usuario.github.io/rflowp/). Hay que decírselo a la construcción, o la PWA quedará apuntando a la raíz del dominio y el navegador se negará a instalarla: 

# Linux, macOS
RFLOWP_BASE=/rflowp/ npm run build

# Windows, PowerShell
$env:RFLOWP_BASE='/rflowp/'; npm run build

# Windows, Git Bash — el prefijo es obligatorio o convierte
# la ruta en «C:/Program Files/Git/rflowp/»
MSYS_NO_PATHCONV=1 RFLOWP_BASE=/rflowp/ npm run build

Cómo comprobar que quedó bien

Abre dist/manifest.webmanifest. Sus campos start_url y scope tienen que coincidir con la carpeta desde la que servirás la app. Si dicen / y la app vive en /rflowp/, no se instalará.

Publicación automática en GitHub Pages

El repositorio ya trae .github/workflows/publicar.yml. Para activarlo: en el repositorio, Settings → Pages → Source: GitHub Actions, y ajusta RFLOWP_BASE dentro del archivo al nombre de tu repositorio. A partir de ahí cada cambio en main se publica solo, y no se publica si fallan las pruebas.

Si lo sirves con tu propio nginx

server {
    listen 443 ssl;
    server_name algoritmos.ejemplo.mx;
    root /var/www/rflowp;

    # El service worker NUNCA debe quedarse cacheado: si el navegador
    # se queda con uno viejo, los alumnos no reciben las actualizaciones.
    location = /sw.js {
        add_header Cache-Control "no-cache";
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}

Cómo la instala cada alumno

Una vez publicada, no hay nada que descargar de ninguna tienda: se abre la dirección y se instala desde el propio navegador. Esto ya viene explicado en el instructivo del alumno; aquí está lo que conviene que sepas tú.

Sistema Cómo Lo que hay que vigilar
Android Chrome: menú → Instalar aplicación Sin problemas. Es la plataforma donde todo funciona como está previsto.
iPhone / iPad Safari: Compartir → Agregar a inicio Solo Safari puede instalarla. Desde Chrome en iPhone no aparece la opción, y varios alumnos se atascarán ahí. Además, lo que guarden en Safari y lo que guarden en la app instalada son almacenes distintos: hay que instalarla antes de empezar a trabajar.
Windows / macOS / Linux Chrome o Edge: icono de instalar en la barra de direcciones Firefox no instala PWAs; funciona igual como página web normal.

Los datos de iOS pueden borrarse solos

Safari borra los datos de un sitio tras siete días sin usarlo. Las apps instaladas en la pantalla de inicio están exentas de ese plazo, y RFlowP además pide almacenamiento persistente al arrancar. Pero es una razón más para insistir en que la instalen de verdad y no la usen como pestaña suelta.

Las dos vías nativas, y por qué probablemente no las necesitas

Android en Google Play

Se puede empaquetar la PWA como aplicación de Play Store con Bubblewrap. Necesitas: cuenta de desarrollador (25 USD una sola vez), generar y custodiar un keystore —si lo pierdes no puedes volver a actualizar la app nunca—, publicar un archivo de verificación en tu dominio, y pasar la revisión de Google.

Para un curso no compensa. «Agregar a inicio» deja exactamente el mismo icono en la pantalla del alumno, sin trámites y con actualizaciones inmediatas. Solo tiene sentido si la institución exige que esté en la tienda.

iPhone en la App Store

No hay atajo: exige 99 USD al año, un contenedor nativo y pasar revisión, que además históricamente rechaza aplicaciones que son solo un envoltorio de una web. No es una vía realista para un curso.

Programa de escritorio con Tauri

Es la única de las tres que aporta algo de verdad: una build de escritorio permite desactivar las herramientas de desarrollo, que es la forma barata de subir la barrera anti-copia. Requiere instalar Rust y añadir la carpeta src-tauri/, que hoy no está en el proyecto: es un camino documentado, no algo que funcione ahora mismo.

Si algún día haces la build de escritorio, avísales antes

El programa de escritorio y la versión web son orígenes distintos: un alumno que use las dos tendría dos identidades separadas, con llaves distintas, y lo guardado en una no se abre en la otra. Hay que elegir una de las dos para todo el grupo, no ofrecer ambas.

La llave incluida con la app

La app se compila con una llave pública dentro, para que funcione desde el primer arranque. Sin ella, un alumno que guarda antes de recibir la llave de su profesor produciría archivos que nadie más podría abrir.

Que esa llave esté en un repositorio público no la debilita: es pública, sirve para cifrar hacia el profesor y no para descifrar nada. Lo que jamás se sube es la privada, que vive en llaves-profesor/, ignorada por git.

Si reutilizas este proyecto para tu curso, genera la tuya

Quien clone y compile este repositorio obtiene la misma llave incluida. Si no la reemplazas, tus alumnos estarían cifrando hacia el dueño de la privada de este repositorio, no hacia ti, y no podrías abrir sus entregas. 

node scripts/generar-llave-del-curso.mjs "Algoritmos 3A 2026"

Escribe la pública en src/crypto/llave-del-curso.ts —que sí se sube— y la privada en llaves-profesor/ —que no—. Después basta con reconstruir y publicar. La llave que un profesor importe a mano desde la app sustituye a la incluida en ese dispositivo.

Laboratorio sin internet

Si el aula no tiene salida a internet, el proyecto trae un servidor HTTPS para la red local. Con la app ya construida (npm run build): 

npm run servidor

Imprime las direcciones de esta computadora en la red. Todos los aparatos tienen que estar en la misma wifi.

Con certificado autofirmado la app se ve, pero no se instala

Es la trampa de esta ruta. npm run certificados genera un certificado en un segundo, pero el navegador marcará la página como insegura, y el service worker no se registra en una página con error de certificado. Sin service worker no hay instalación ni funcionamiento sin conexión: justo lo que se quería.

Sirve para comprobar rápido que la app carga desde otro equipo. No sirve para dar la clase.

Para que sí se pueda instalar: mkcert

mkcert crea una autoridad certificadora local y emite certificados que los aparatos sí aceptan: 

mkcert -install
mkcert -cert-file certs/cert.pem -key-file certs/key.pem <IP-de-esta-compu> localhost
npm run servidor

Después hay que instalar la autoridad de mkcert en cada aparato: mkcert -CAROOT dice dónde está el archivo rootCA.pem que tienes que pasarles. En Android se añade en Ajustes → Seguridad → Credenciales; en iPhone hay que instalar el perfil y además activarlo en Ajustes → General → Información → Certificados de confianza, que es un paso que casi nadie encuentra solo.

Piénsalo dos veces antes de elegir esta ruta

Estás pidiendo a treinta alumnos que instalen tu autoridad certificadora en su teléfono personal. Técnicamente eso te permitiría interceptar su tráfico cifrado; no lo vas a hacer, pero es razonable que alguno no quiera, y estás en tu derecho de que te lo cuestionen.

La alternativa es mucho más simple: que instalen la app una vez desde la dirección pública —en su casa, o con datos móviles cinco minutos— y después el laboratorio puede estar sin internet todo el semestre. La app ya no necesita la red para nada.

Actualizar la app durante el curso

Publica la nueva versión y ya está: la app se actualiza sola la próxima vez que el alumno la abra con conexión. No tienen que reinstalar nada ni pierden sus archivos, porque la dirección no cambió.

Puede tardar unos minutos en verse

GitHub Pages guarda el index.html en caché un rato. Justo después de publicar, un aparato que ya había abierto la app puede seguir viendo la versión anterior hasta que la caché expire o se recargue forzando. Es transitorio y se arregla solo; solo hay que saberlo para no pensar que la publicación falló.

Lo único que sí rompe compatibilidad

Cambiar el formato de los archivos .algx. Si en algún momento subes la versión del formato, las entregas viejas dejarán de abrirse con un mensaje claro, pero dejarán de abrirse. Recoge y califica lo pendiente antes de un cambio así.

Antes de repartir la dirección

  • La dirección abre con candado (https) y es la definitiva: https://rodolfoluna.github.io/rflowp/
  • El navegador ofrece instalarla: si no aparece la opción, revisa start_url y scope en el manifiesto.
  • La probaste en un Android y en un iPhone reales, instalada desde la pantalla de inicio, no solo en la computadora.
  • Con el aparato en modo avión, la app abre y deja trabajar.
  • Creaste la llave del curso y la privada está respaldada en dos lugares.
  • Tienes listo el archivo de llave pública para repartir el primer día.
  • Imprimiste el instructivo del alumno con la dirección escrita en él.
Este manual acompaña a los instructivos de una página de docs/. Para lo que la app protege y lo que no, mira la sección correspondiente del README.md del proyecto: conviene leerla antes de apoyarse en ella para calificar.
